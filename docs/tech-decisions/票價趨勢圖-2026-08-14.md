| ⚡ 開發速度 | ⭐⭐⭐⭐⭐（mockup 程式碼直接移植） | ⭐⭐⭐（先建 toolchain＋學框架慣例） |
| 🔧 維護成本 | ⭐⭐⭐⭐⭐（3 檔無依賴） | ⭐⭐⭐⭐（依賴升級、建置檔維護） |

| 💰 成本 | ⭐⭐⭐⭐⭐（$0，零 CI 變更） | ⭐⭐⭐⭐（CI 分鐘數、依賴風險） |

### D4 資料載入策略

**決策內容**（整合 UIUX 實作建議 #2/#3/#4）：

```
1. fetch ../api/index.json（fetch 帶 {cache:'no-cache'} 重新驗證，確保每週更新即時可見）
   → 取得 routes、trips 清單、generated_at、總檔數
2. 對目前航線並行 fetch 40 個 trip 檔（Promise pool，concurrency ≤ 8）
   → 頂部顯示進度「已載入 N/40」
   → 成功即存入 Map<url, json> 記憶體快取；切航線回東京不再重載
3. 每週聚合（資料層單一模組，圖表與 Summary 共用）：
   → 每航班 history 取最新一筆 price_total → 每週最低價 = min
   → 全域平均 = 全部週最低價平均；最低價標記 = min 點
   → 缺資料週（檔案不存在 / 無航班）標記斷點；售罄週標記「售罄」
4. 互動全部吃記憶體資料：航班切換、範圍篩選、航線切換皆 <1s 即時重繪（符合驗收「第二次 <1s」）
5. 更新時間警示：generated_at 距今 >14 天 → 頁首黃色警示
6. 錯誤處理：index 失敗 → 全頁錯誤卡＋重試（連續失敗顯示錯誤代碼）；
   個別 trip 缺檔 → 斷點＋「本週無資料」，不阻塞其餘載入
7. 旺季區間（過年/櫻花）以設定常數維護，隨年調整
```

**理由**：
- 全量資料 <70KB、80 個小檔 → 「一次全載＋記憶體快取」比「按需 lazy 載入」更簡單且更快，符合互動流程「第二張圖 <1s」驗收
- concurrency 8 而非無腦 `Promise.all`×80：對行動網路較友善、避免連線突發；HTTP/2 下依然近並行
- `cache:'no-cache'` 只用在 index.json（目錄/時間戳來源）；trip 檔走瀏覽器預設快取（ETag 重新驗證），每週更新可被看見

## 4. 決策理由（彙總）

### 為什麼選擇此方案
1. **零建置、零依賴、零設定變更**：3 個靜態檔 commit 即上線；Pages 沿用現有 root 部署；不新增任何 runtime/CI 依賴——與「零維運、$0 成本」的既有決策（爬蟲、靜態 API）完全一致。
2. **mockup 已是可移植的參考實作**：UIUX 設計文件已用真實資料驗證過手繪 SVG 的完整視覺與無障礙行為（含 375px mobile 模式、深色主題），實作僅需「移植繪圖邏輯＋接資料層」，開發風險最低。
3. **資料規模使架構極簡化**：全量資料 <70KB、80 小檔、單頁儀表板——不需要框架、不需要圖表庫、不需要 lazy loading、不需要測試框架；每個「現代化工具」在此規模下都是淨負債。

### 為什麼放棄其他方案
- **Vite＋React/Vue（D1-B）**：單頁儀表板規模下元件化收益遠低於 toolchain 維運成本；綠地前端未來真要擴再遷移無包袱。
- **Chart.js / ECharts（D2-B/C）**：需求是極簡折線圖，手繪 SVG 已全覆蓋；CDN 庫引入第三方可用性風險、主題對應成本與 1MB 載入量。
- **docs/ 部署（D3-B）**：需改 Pages 設定，且把 runtime 頁面混入文件目錄；`web/` 語意與設定成本皆優。
- **測試框架（D6）**：Jest/Vitest/playwright-test 需導入 node toolchain；聚合邏輯規模小，腳本化 E2E（真實＋mocked）已達驗收門檻。

## 6. 風險登錄

| 風險 | 可能性 | 影響 | 緩解措施 |
|------|--------|------|---------|
| `build_api.py` 欄位結構變動致前端解析失敗 | 中 | 高 | 資料層集中於聚合模組單點改；T8 E2E 以真實 api/ 資料驗證；改 API 時同步跑驗證 |
| 手繪 SVG 隨需求變複雜（多視圖/比較）難維護 | 低 | 中 | 40 點規模有限；出現複雜化徵兆時升級 Chart.js/ECharts（D2 已預留） |
| 旺季日期每年手動更新遺漏 | 高 | 低 | 集中於設定常數＋程式註解「每年更新」；明年可評估由爬蟲設定自動帶出 |
| trip 檔 history 逐年增長變大 | 低 | 低 | 目前每檔 <1KB；若多年後變大，`build_api.py` 可聚合/截斷（屆時另決策） |
| 瀏覽器並發 fetch 限制拖慢載入 | 低 | 低 | concurrency 8 limiter＋HTTP/2 多工；全量 <70KB 最壞情況仍可接受 |
| jsDelivr 快取延遲（若使用者切換資料源） | 低 | 低 | 預設 Pages 直連相對路徑；不做 CDN 切換的預設值 |
