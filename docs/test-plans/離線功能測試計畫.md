## 2. 前端單元測試（快取層與比對邏輯模組）

> 說明：本專案無後端，「快取持久化 / generated_at 比對 / 增量補載 / 離線降級 / 空間不足」邏輯皆位於前端資料層模組（`web/cache.js` 的 `saveCache` / `loadCache` / `compareGeneratedAt` / `diffTripLists` / `mergeCache` / `fallbackLatestOnly` / `resolveOnlineStatus` / `estimateSize` 等純函式），故 @business-rules 與部分 @error-handling 的純邏輯由本層單元測試覆蓋。Node 環境無 IndexedDB/localStorage，測試透過注入 in-memory storage adapter 執行；瀏覽器行為由 §3/§4 驗證。

### 2.1 快取持久化與比對模組（web/cache.js）

| # | 測試名稱 | Given | When | Then |
|---|---------|-------|------|------|
| F-01 | 首次載入寫入完整快取（BDD: 首次訪問連網載入全部資料並寫入快取） | 首次載入成功：index（含 generated_at/routes/trips 清單）＋目前航線 40 個 trip 週資料 | 執行 saveCache(index, routeData) | 快取寫入 index 摘要、目前航線週資料與 saved_at；回傳成功 |
| F-02 | 快取讀取回傳上次資料（BDD: 再次訪問且伺服器無新資料時快取秒開） | 本地已有快取 | 執行 loadCache() | 回傳 { generated_at, routes, trips, savedAt, routeData }，可供立即繪圖 |
| F-03 | 無快取判定＝首次訪問（BDD: 首次訪問連網載入全部資料並寫入快取） | 全新儲存（adapter 內無任何鍵） | 執行 loadCache() | 回傳 null → 流程判定為首次訪問（需連網全量載入） |
| F-04 | generated_at 相同 → 「已是最新」不重抓（BDD: 更新比對以 index.json 的 generated_at 為唯一基準） | 本地 generated_at = 伺服器 generated_at | 執行 compareGeneratedAt(local, server) | 回傳 'same' → 顯示「已是最新」，不重新抓取任何 trip 檔 |
| F-05 | generated_at 伺服器較新 → 增量更新（BDD: 再次訪問且伺服器有新資料時只補載變更部分） | 伺服器 generated_at 比本地記錄新 | 執行 compareGeneratedAt(local, server) | 回傳 'newer' → 進入增量補載流程 |
| F-06 | generated_at 伺服器較舊 → 過時警示（BDD: 更新比對以 index.json 的 generated_at 為唯一基準） | 伺服器 generated_at 比本地記錄舊 | 執行 compareGeneratedAt(local, server) | 回傳 'server_stale' → 顯示「資料可能過時」警示，不覆寫本地新資料 |
| F-07 | 增量清單只含新增/變更 trip 檔（BDD: 再次訪問且伺服器有新資料時只補載變更部分） | 本地 trips = [A,B,C]，伺服器 trips = [A,B,C,D]（D 新增） | 執行 diffTripLists(local, server) | 只回傳 [D]；A/B/C 不重抓（未變更者以快取為主） |
| F-08 | 增量合併寫回快取（BDD: 再次訪問且伺服器有新資料時只補載變更部分） | 快取為舊版，增量檔載入成功 | 執行 mergeCache(localCache, newTrips) | 快取 trips 更新、generated_at 更新為新版、saved_at 更新 |
| F-09 | 手動更新強制重新驗證（BDD: 手動更新於連網時永遠可用且強制重新驗證） | 頁面已顯示「已是最新」 | 以 force=true 執行更新流程 | 仍強制重新抓取 index.json 並比對 generated_at，不受自動比對結果影響 |
| F-10 | 快取以瀏覽器為單位（BDD: 快取以瀏覽器為單位且離線能力從第二次訪問起生效） | 瀏覽器 A 已寫入快取（per-origin storage） | 在瀏覽器 B／無痕環境執行 loadCache() | 回傳 null → 等同首次訪問需連網；離線能力從該瀏覽器第二次訪問起生效 |
| F-11 | 空間不足 → quota_error 訊號（BDD: 瀏覽器儲存空間不足時降級為只保留最新） | storage adapter 寫入拋 QuotaExceededError | 執行 saveCache | 回傳 { status: 'quota_error' }，不拋例外打斷頁面流程 |
| F-12 | 空間不足降級「只保留最新」（BDD: 瀏覽器儲存空間不足時降級為只保留最新） | 收到 quota_error | 執行 fallbackLatestOnly | 只保留目前航線資料與最新 generated_at，捨棄其他航線；頁面仍可運作 |
| F-13 | 離線判定：onLine + 實際請求結果（BDD: 連網狀態誤判時以實際請求結果為準） | 瀏覽器回報 navigator.onLine=true 但實際請求失敗 | 執行 resolveOnlineStatus(onLine, requestOk=false) | 判定為離線（請求失敗優先），不因 onLine 誤判而卡住 |
| F-14 | 離線時不發請求直接以快取繪圖（BDD: 離線訪問顯示快取資料與離線橫幅） | 離線且有快取 | 開啟頁面執行初始流程 | 不發任何 api 請求，直接以快取資料繪圖並顯示「上次更新 HH:MM」 |
| F-15 | 「上次更新 HH:MM」與離線橫幅時間格式（BDD: 離線訪問顯示快取資料與離線橫幅） | saved_at = 某時刻（含當日） | 執行格式化函式 | 更新時間顯示「上次更新 HH:MM」；離線橫幅為「離線模式 · 顯示上次資料（HH:MM）」 |
| F-16 | 手動更新按鈕可用性（BDD: 離線時按「手動更新」按鈕停用並提示） | 離線狀態 | 判定按鈕狀態 | 停用並顯示「離線中，無法更新」；恢復連網後自動恢復可用 |
| F-17 | 資料容量估算在配額內（BDD: 全量資料容量在瀏覽器儲存配額內） | index ~9KB ＋ 159 個 trip 檔（每檔約 1–2KB） | 執行 estimateSize | 全量約數百 KB，低於正常瀏覽器儲存配額（≳5MB），且保留空間不足降級機制 |
| F-18 | 伺服器檔案移除 → 本地一併移除（BDD: 伺服器檔案被移除時一併移除本地快取） | 本地快取含某航線 trip 檔 X，伺服器已移除（404 或不在新 trips 清單） | 執行 syncRemovedFiles | 本地 X 一併移除；以伺服器資料為準，不顯示錯誤卡 |
| F-19 | 增量部分失敗 → 成功者先更新、失敗者保留舊版（BDD: 增量補載部分 trip 檔失敗時保留舊版並下次重試） | 增量補載中部分 trip 檔載入失敗 | 執行 mergeCache(partial) | 成功檔更新並寫回；失敗檔保留舊版資料，並記入 retryList |
| F-20 | 重試清單下次只重試失敗檔（BDD: 增量補載部分 trip 檔失敗時保留舊版並下次重試） | retryList = [X] | 下次自動/手動更新時計算載入清單 | 只重試 X（與增量清單合併去重），其餘不重抓 |
| F-21 | 離線切換未載入航線判定（BDD: 離線時切換到從未載入的航線顯示提示並停留原航線） | 離線且快取僅含東京 routeData | 執行 hasCache('TPE-KIX') | 回傳 false → 顯示「此航線尚未下載，需連網」，停留原航線、無錯誤卡 |
| F-22 | 離線切換已快取航線（BDD: 離線時切換到已快取航線仍可完整操作） | 離線且快取含東京與大阪 routeData | 切換東京→大阪 | 直接以快取繪圖；航班/範圍/hover/Summary 資料來自快取 |
| F-23 | 連網切換未載入航線載入並寫入快取（BDD: 連網時切換到未載入航線會載入該航線並寫入快取） | 連網、東京已載入並有快取 | 切換到大阪（尚未載入） | 連網載入大阪 trip 資料並寫入快取；圖表與摘要更新為大阪 |
| F-24 | 手動更新無新版 → 資料維持原狀（BDD: 手動更新且伺服器無新版時維持資料並顯示「已是最新」） | 連網、伺服器 generated_at 與本地相同 | 點「手動更新」（force） | 強制抓 index 比對後資料維持原狀，顯示「已是最新」 |

### 2.2 補充測試（智能補充：並發 / 依賴失敗 / 邊界）

| # | 測試名稱 | Given | When | Then |
|---|---------|-------|------|------|
| F-25 | 增量更新與使用者操作競態（補充：並發） | 增量補載進行中使用者切換航線/範圍 | 回應先後抵達（後到者先回） | 只套用最新操作結果，過期回應丟棄（沿用 loadToken / AbortController 機制） |
| F-26 | 背景比對失敗不中斷瀏覽（補充：依賴失敗；BDD: 背景比對時 index.json 抓取失敗不中斷瀏覽並可重試） | 背景比對時 index.json 抓取失敗 | 執行背景更新流程 | 狀態機進入「更新失敗，稍後自動重試」；瀏覽與圖表操作不中斷；下次可重試 |
| F-27 | 斷線重連自動恢復（補充：依賴失敗；BDD: 斷線重連後不需重新整理頁面即可恢復自動更新） | 背景比對/更新流程因斷線失敗 | 網路恢復（online 事件 + 請求成功） | 自動恢復更新流程，不需重新整理頁面；資料與更新狀態回到最新 |
| F-28 | 容量估算邊界（補充：邊界） | trips 清單為空／極大（如 1000 檔） | 執行 estimateSize | 空清單 → 0；極大清單 → 超過配額時觸發降級機制訊號 |

## 3. 整合測試（Playwright route interception + offline 控制）

> 使用 Playwright 的 `route` 攔截 `api/index.json` 與 `api/trips/*.json`、`context.setOffline(true/false)` 控制連線、`addInitScript` 模擬空間不足，驗證「快取層 ↔ 資料層 ↔ 圖表層」整合行為。

| # | 測試名稱 | Given | When | Then |
|---|---------|-------|------|------|
| INT-01 | 首次訪問資料管線＋快取寫入（BDD: 首次訪問連網載入全部資料並寫入快取） | 全新 browser context（無任何儲存） | 開啟頁面並等待載入 | 先顯示全頁骨架與載入進度；載入 index + 目前航線 trips；快取寫入（evaluate 檢查 storage 非空）；圖表繪出；更新時間顯示；手動更新可用 |
| INT-02 | 快取秒開＋背景比對無新資料不重抓（BDD: 再次訪問且伺服器無新資料時快取秒開並顯示「已是最新」） | 同 context 已建立快取（記錄 generated_at）；route 統計 api 請求數 | 再次開啟頁面 | 圖表立即以快取繪出（無全頁骨架）；index.json 請求 1 次；trips 請求 0 次；顯示「已是最新」 |
| INT-03 | 背景比對有新資料只補載變更（BDD: 再次訪問且伺服器有新資料時只補載變更部分） | 快取舊 generated_at + 5 個 trip；伺服器新版 + 新增 1 檔 | 再次開啟頁面 | trips 只請求新檔 1 次（舊檔 0 次）；快取與更新時間同步更新；圖表更新為最新；「已是最新」 |
| INT-04 | 離線訪問零請求＋快取繪圖（BDD: 離線訪問顯示快取資料與離線橫幅） | context 有快取；context.setOffline(true) | 開啟頁面 | 無任何 api 請求（請求計數 = 0）；以快取繪圖；離線橫幅顯示；手動更新停用 |
| INT-05 | 離線切換已快取雙航線（BDD: 離線時切換到已快取航線仍可完整操作） | 快取含東京＋大阪；離線 | 東京↔大阪之間切換 | 兩航線皆直接以快取繪圖；航班/範圍/hover/Summary 正常；無 api 請求 |
| INT-06 | 空間不足降級（BDD: 瀏覽器儲存空間不足時降級為只保留最新） | addInitScript 使儲存寫入拋 QuotaExceededError | 首次載入（連網）完成 | 顯示「空間不足，已保留最新資料」；以「只保留最新」策略運作；頁面圖表正常 |
| INT-07 | 斷線重連自動恢復（BDD: 斷線重連後不需重新整理頁面即可恢復自動更新） | 背景比對失敗（離線） | context.setOffline(false) | 自動恢復更新流程（不需 reload）；資料與更新狀態回到最新 |
| INT-08 | 瀏覽器快取隔離（BDD: 在無痕視窗或另一瀏覽器開啟等同首次訪問） | context A 已建立快取 | context B（無痕，storage 不共享）開啟頁面 | B 視為首次訪問（無「上次更新」、需連網載入）；載入一次後 B 才具備快取 |

## 4. 端對端測試（Playwright + chromium）

> 離線情境透過 `context.setOffline(true/false)` 與 `page.route` 模擬；快取預置透過同 context 先載入一次（或 `add_init_script` 預寫 storage）達成。

| # | 測試名稱（來源 BDD） | 操作步驟 | 預期結果 |
|---|---------|---------|---------|
| E2E-01 | 首次訪問載入全部資料並寫入快取（@smoke @happy-path @p0） | 全新 context 開啟頁面 → 觀察載入過程 → 等待圖表 | 先顯示全頁載入骨架與進度；圖表繪出；更新時間顯示（generated_at）；「手動更新」按鈕可用；evaluate 檢查快取已寫入（storage 非空） |
| E2E-02 | 再次訪問無新資料快取秒開（@smoke @happy-path @p0） | 同 context 二次 goto，route 統計 index/trips 請求數 | 顯示「上次更新 HH:MM」；無全頁載入骨架；trips 請求數 = 0；更新時間旁顯示「已是最新」 |
| E2E-03 | 再次訪問有新資料增量補載（@happy-path @p0） | 第一次載入（舊 generated_at）→ 第二次 route 換新版 index + 新增 1 trip 檔 | 頁面先以快取立即繪圖；只請求新增 trip 檔（舊檔 0 次）；快取與更新時間更新；圖表/摘要更新為最新價格；顯示「已是最新」 |
| E2E-04 | 離線訪問顯示快取與離線橫幅（@smoke @happy-path @p0） | 建立快取 → context.setOffline(true) → 開啟頁面 | 直接以快取繪製趨勢圖；頁首離線橫幅「離線模式 · 顯示上次資料（HH:MM）」；航班切換、日期範圍、hover、Summary 三卡皆可操作；「手動更新」停用並顯示「離線中，無法更新」 |
| E2E-05 | 連網切換未載入航線載入並寫入快取（@happy-path @p0） | 載入東京 → 切「大阪 KIX」tab（route 提供大阪檔） | 系統連網載入大阪 trip 資料並寫入快取；圖表與摘要更新為大阪航線資料 |
| E2E-06 | 手動更新伺服器有新版（@happy-path @p0） | 快取舊版 → 點「手動更新」（route 換新版 index + 變更 trip） | 強制重新抓取 index.json 並比對；只補載變更 trip 檔；快取與更新時間更新；圖表顯示最新價格並標示「已是最新」 |
