## 概述

讓公開訪客再次開啟頁面時「快取優先 + 增量更新」：有網路時只補載變更的資料（條件式 GET），沒網路時直接以 IndexedDB 快取瀏覽上次載入的資料（含離線開頁），並保留手動強制更新；純靜態、零依賴、零維運。核心包含：

1. **快取層（web/cache.js，新增）**：IndexedDB 薄 Promise 封裝（meta / units 兩 store）+ 同步決策純函式（比對 / 增量清單 / 合併 / 降級 / 容量估算），UMD 匯出對齊 `aggregate.js`，Node `node:test` 可直接測試。
2. **主程式改寫（web/app.js）**：cache-first 啟動流程（秒開 → 背景比對 → 增量同步 → 記憶體 routeCache → 圖表）、離線狀態層（橫幅 / tab 提示 / 按鈕停用 / 錯誤卡）、手動更新（強制重新驗證）；既有圖表 / 互動 / Summary 邏輯不動。
3. **Service Worker（web/sw.js，新增）**：極簡 SWR 策略，只 precache app shell 6 檔（index.html / styles.css / app.js / aggregate.js / cache.js / sw.js），**不攔 `api/`**——兜底「離線開頁」硬需求（情境 D）。
4. **靜態資源（web/index.html / styles.css / web/aggregate.js）**：離線橫幅 DOM、手動更新按鈕、同步狀態文字、tab 未下載提示、`formatLastUpdated` 純函式。
5. **驗證腳本（tests/unit/cache.test.js + tests/e2e_offline.py，新增）**：純函式單元測試（F-01~F-28）+ 離線 E2E（E2E-01~23 / INT-01~08）；既有 `e2e_smoke.py` 不動（回歸門檻）。

章節取捨（依功能類型）：純前端功能，無後端實作章節（§1 略）；無新增 endpoint，§3 以「消費合約」形式列出既有靜態 API 如何被消費（含 ETag 條件式請求）；跨「GitHub Pages 靜態 API → IndexedDB → 記憶體 → 圖表」資料流 → §4；快取版本 / SW 生命週期 / 頁面狀態機 → §5；BDD 全部 @edge-case 與 E1–E8 → §6；新 UI（離線橫幅 / tab 提示 / 按鈕狀態）→ §7；開發順序依 T1–T9 → §8；SW 於 GitHub Pages 註冊注意事項 + S1 Spike 結果 → §9。

### 2.2 web/cache.js — 快取層（T1 + T2）

#### 2.2.1 儲存 schema（D2 / D7）

```
db: airtickets-cache (version 1)
  store "meta"（單鍵 'meta'）:
    {
      version: 1,                 // cache schema 版本；bump → 全量重同步（D7 / B1 相容）
      generatedAt: ISO|null,      // 伺服器 index.generated_at（快取資料對應版本，比對基準 D3）
      syncedAt: ISO|null,         // 最後一次成功同步時間（「上次更新 HH:MM」來源）
      indexTrips: string[]|null,  // index.trips 快照（離線時推 unit 清單 / hasCache 判斷用）
      routeLoadedAt: { [routeId]: ISO },  // 各航線最後載入時間（離線可看範圍）
      lastError: null|'partial'|'compare_failed',  // 上次同步錯誤標記
      retryList: string[],        // E4：失敗待重試 unit URL
    }
  store "units"（key = unitUrl）:
    { [unitUrl]: { etag: string|null, json: object } }
    ↑ unit 今天 = api/trips/{route}/{dep}_{ret}.json；B1 後 = api/routes/{route}.json（D7）
```

- **B1 相容（D7）**：`routeUnitsFromIndex(index)` 是唯一的「index → unit 清單」映射點。今天從 `index.trips` 依路徑段 `/{route}/` 篩出各航線 trip URL；B1 後改讀 `index.routes` → `api/routes/{route}.json`。比對 / 增量 / ETag / 降級機制全部不動，僅 bump `version` 觸發一次全量重同步。
- **ETag 來源**：首次成功抓取 unit 時讀 `res.headers.get('etag')` 存入；同步時回送 `If-None-Match`。伺服器無 ETag 或無視條件式請求（回 200）→ 直接覆寫快取，功能正確、僅少掉增量節省（Spike S1 已驗證 Pages 有 ETag 且支援 304，見 §9.3）。

#### 2.3.2 cache-first 啟動流程（init 改寫）

```javascript
async function init() {
  // 0. 註冊 SW（僅 http(s) 且支援；失敗靜默降級，file:// 下不註冊 — §9.1）
  if ('serviceWorker' in navigator && /^https?:$/.test(location.protocol)) {
    navigator.serviceWorker.register('sw.js').catch(() => {}); // 靜默，不影響功能
  }
  renderRouteTabs(); renderRangeSeg(); initControls();   // 既有，不動

  // 1. 讀 IDB 快取（E8：開啟失敗 → 視同無快取，走既有首次載入路徑並維持記憶體 routeCache）
  let cached = null;
  try { cached = await OfflineCache.loadCache(cacheStore); } catch (e) { /* E8 降級 */ }
  if (!cached) { await firstLoad(); return; }            // 情境 A / E1
  CACHE = cached;

  // 2. 有快取 → 立即以快取繪圖（秒開，情境 B/C/D）+ 「上次更新 HH:MM」
  INDEX = { trips: CACHE.meta.indexTrips || [] };
  await drawCurrentRouteFromCache();

  // 3. 離線 → 橫幅 + 不發任何請求 + E2 降級（情境 D）
  if (!navigator.onLine) { enterOffline(); return; }

  // 4. 連網 → 背景比對（情境 B/C；E3 失敗 → 「更新失敗，稍後自動重試」+ online 事件重試）
  backgroundCompare();
}
```

**drawCurrentRouteFromCache()**：與既有 `drawCurrentRoute` 相同出口，但資料來源改為 `OfflineCache` 的 units（route → Week[] 聚合）而非網路；缺該航線（hasCache=false）→ 空狀態（離線時由 E2 提示兜底）。

**firstLoad()（情境 A / E1）**：既有全量載入流程（骨架 + concurrency 8 + routeCache），差別：
- `fetchIndex` 改為回傳 `{ json, etag }`（記錄 ETag）；
- trip 載入改帶本地 etag（首次無 → 不帶）並記錄回應 etag；
- 全部成功後 `saveCache(meta, units)`（meta.generatedAt = index.generated_at、syncedAt = now、indexTrips = index.trips、routeLoadedAt[route] = now）；
- **失敗且無快取 → E1 錯誤卡「需要網路才能首次載入資料」+ 重試**（連線後點重試重跑 firstLoad）。

```javascript
/** 進入離線：橫幅「離線模式 · 顯示上次資料（HH:MM）」；不發請求；手動更新停用（E7）；E2 降級 */
function enterOffline() {

function onOnline() {

  setRefreshDisabled(false, '手動更新');

function showRouteHint(tabBtn) { /* 建立 .rtab .hint 元素；setTimeout 移除 */ }

function markCompareFailed() {

  CACHE.meta.lastError = 'compare_failed';   // 下次開啟頁面沿用（F-26）
```

#### 2.3.5 手動更新（T5 / D6 / E7）

```javascript
/** 手動更新按鈕：連網才可用；離線停用（E7） */
async function manualUpdate() {
  if (syncing || !navigator.onLine) return;
  syncing = true;
  setRefreshDisabled(true, '更新中…');
  try {
    await incrementalSync({ force: true });   // 強制 no-cache 抓 index + 完整增量同步
    // 完成：syncStatus「已是最新」；update 有變更 → 圖表/摘要/更新時間已更新（情境 E）
    // force 下即使 decideSync 為 fresh 也確實重新抓過 index（BDD 手動更新無新版維持原狀）
  } finally {
    syncing = false;
    setRefreshDisabled(!navigator.onLine, navigator.onLine ? '手動更新' : '離線中，無法更新');
  }
}
refreshBtn.addEventListener('click', manualUpdate);
```

### 2.4 web/sw.js — app shell precache（T6 / D1）

極簡 SW（目標 ~40 行）：只 precache app shell 6 檔（SHELL 含 `cache.js`——app.js 執行期即依賴 `OfflineCache` 全域，cache.js 必須進 shell 才能離線開頁，實作偏離 Tech Decision 的 5 檔），SWR（stale-while-revalidate），**不攔 `api/`**——且 `api/` 位於 SW scope（`/AirTicketsPrice/web/`）之外，結構上也不可能攔到（§9.1）。

```javascript
/* 離線功能 — app shell Service Worker（方案 C：只兜頁面殼，不攔 api/）
   對照：docs/tech-decisions/離線功能-2026-08-15.md D1；docs/development/離線功能.md §2.4 / §9 */
'use strict';

const CACHE = 'airtickets-shell-v1';          // 版本化；部署 bump → activate 清舊 cache
const SHELL = [                               // 僅 6 檔（tech decision D1：不攔 api/）
  'index.html',
  'styles.css',
  'app.js',
  'aggregate.js',
  'cache.js',
  'sw.js',
];

/* install：precache shell；任一個失敗 → 整體失敗（install 不完成，下次再試） */
self.addEventListener('install', e => {
  e.waitUntil(caches.open(CACHE).then(c => c.addAll(SHELL)).then(() => self.skipWaiting()));
});

/* activate：刪除非目前版本 cache（避免舊 shell 殘留） */
self.addEventListener('activate', e => {
  e.waitUntil(caches.keys().then(keys =>
    Promise.all(keys.filter(k => k !== CACHE).map(k => caches.delete(k)))
  ).then(() => self.clients.claim()));
});

/* fetch：只攔「同源 + 命中 shell 清單」的 GET →
 *   cache-first 回傳 + 背景 revalidate 更新快取（SWR，不回推頁面——資料更新由 app.js 的 IDB 層負責）
 *   navigation 請求（如 /web/ 或 /web/index.html）→ cache-first：先比對 request，miss 再比對
 *   'index.html'（目錄導覽共用同一份 shell）；仍 miss → fallback network。
 *   其餘（含 api/** 與跨源）→ 直接 return，絕不攔截。
 */
self.addEventListener('fetch', e => {
  const u = new URL(e.request.url);
  if (e.request.method !== 'GET' || u.origin !== location.origin) return;
  const base = new URL('./', self.registration.scope).pathname;   // …/web/
  const isShell = SHELL.some(p => u.pathname === base + p);
  const isNav = e.request.mode === 'navigate';
  if (!isShell && !isNav) return;               // 非 shell、非導覽 → 放行（含 api/**，結構上也在 scope 外）
  e.respondWith(
    caches.match(e.request).then(cached =>
      cached || (isNav ? caches.match(base + 'index.html') : undefined)
    ).then(fallback => {
      const net = fetch(e.request).then(res => {
        if (res && res.ok) caches.open(CACHE).then(c => c.put(e.request, res.clone()));
        return res;
      }).catch(() => fallback);
      return fallback || net;                   // cache-first；快取 miss → 網路，網路失敗 → 快取
    })
  );
});
```

> 注意：`app.js` / `cache.js` 等被 SW 以 SWR 服務時，瀏覽器重新驗證靠 SW 更新（sw.js 本身每次導覽由瀏覽器檢查，GitHub Pages `max-age=600` → 約 10 分鐘內生效，見 §9.2）。資料層完全不依賴 SW 快取，故 SW 版本與資料版本彼此獨立。

### 2.7 web/aggregate.js 擴充（F-15 對應）

```javascript
/**
 * 更新時間格式化成 'HH:MM'（「上次更新 HH:MM」/ 離線橫幅共用；顯示訪客本地時區）。
 * @param {string|null} iso - syncedAt / generated_at ISO 字串；null → '--:--'
 * @returns {string}
 */
function formatLastUpdated(iso) {
  if (!iso) return '--:--';
  const d = new Date(iso);
  if (Number.isNaN(d.getTime())) return '--:--';
  return d.toLocaleTimeString('zh-TW', { hour: '2-digit', minute: '2-digit', hour12: false });
}
// 加入 PriceAgg 匯出（tests/unit/aggregate.test.js 擴充 F-15 案例）
```

> 時區註記：既有 `formatGeneratedAt` 採 UTC 日期切片（`slice(0,10)`）；「上次更新 HH:MM」為使用者體驗資訊，採**訪客本地時區**（`toLocaleTimeString`）；單元測試以「格式形狀」驗證（`/^\d{2}:\d{2}$/`）而非具體數值，避免時區造成 flaky（附錄 B）。

## 3. API 合約（消費合約）

本功能**不新增任何 endpoint**，僅以既有靜態 API 為資料源，並新增「條件式 GET」消費方式（D4）。

### 3.1 `GET ../api/index.json`（repo root；頁面在 web/ → `../api/index.json`）

| 項目 | 內容 |
|------|------|
| 快取模式 | `{ cache: 'no-cache' }` 強制重新驗證（每次開啟 / 手動更新都重抓，D6） |
| 額外消費 | 記錄 `ETag` response header（首次存入 meta；同步時回送 `If-None-Match`） |
| 欄位 | `generated_at`（比對基準 D3）、`routes`（存在性）、`trips`（unit URL 清單 → `routeUnitsFromIndex`） |
| 比對結果 | `decideSync`：`fresh` 0 個 trip 請求（情境 B 的關鍵成本節省）/ `update` 增量 / `stale` 警示 |

### 3.2 `GET ../api/trips/{route}/{dep}_{ret}.json`（unit；159 檔）

| 項目 | 內容 |
|------|------|
| 首次 | 無條件 GET → 200 → 讀 `ETag` 存 units |
| 同步 | 條件式 GET：`If-None-Match: <本地 etag>`（亦可併送 `If-Modified-Since`，S1 驗證 Pages 兩者皆回 304） |
| 304 | 保留本地（零 body、零下載；S4 以 status 判斷不讀 body） |
| 200 | 覆寫 json + 更新 etag（D4） |
| 404 | 移除本地 unit（E6：以伺服器為準，不顯示錯誤卡） |
| 網路錯誤 / 5xx | 保留舊版 + 記入 retryList（E4） |

### 3.3 條件式請求頭（S1 實測驗證通過，2026-08-15）

| Header | 值 | 伺服器回應 |
|--------|-----|-----------|
| `If-None-Match` | `"6a7f9bfb-231e"`（Pages 回傳的 etag） | **304**（實測） |
| `If-Modified-Since` | `Fri, 14 Aug 2026 22:51:39 GMT` | **304**（實測） |
| （無條件） | — | 200 + `etag` + `cache-control: max-age=600` |

備援：edge 無 ETag 或無視條件式請求 → 回 200 全量覆寫，功能正確僅少增量節省（S1 fallback）。

## 4. 資料流

跨「GitHub Pages 靜態 API → IndexedDB → 記憶體 routeCache → 圖表」的完整管線，含離線分支。

```
                          ┌────────────── 開啟頁面 ──────────────┐
                          ▼                                      ▼
              register SW（app shell 秒開兜底）        loadCache(IDB) → null?
               shell: Cache Storage SWR                 ├─ null（首次/E8）→ 情境 A
               api/: 不攔，放行                        │    fetchIndex(no-cache, ETag)
                                                      │    → fetchTrips 全量（concurrency 8）
                                                      │    → aggregateWeekly → routeCache
                                                      │    → saveCache(meta+units) → buildChart
                                                      ▼
                                 有 meta → 立即以快取繪圖（秒開）+「上次更新 HH:MM」
                                                      │
                              navigator.onLine? ──否──► 離線分支：橫幅 + 不發請求 + E2 降級
                                                      │
                                                      ▼ 是
                                背景比對：fetchIndex（no-cache + 記 ETag）
                                                      │
                                     decideSync(meta.generatedAt, server.generated_at)
                        ┌────────────────┬───────────┴────────────┬──────────────┐
                        ▼ fresh          ▼ update                  ▼ stale         ▼ 失敗（E3）
                   「已是最新」       增量同步：                 「資料可能過時」  「更新失敗，稍後自動重試」
                   0 個 trip 請求   routeUnitsFromIndex(json)     （保留本地新資料） + 30s 排程重試
                                    → diffUnits → 條件式 GET 每個 unit
                                        ├ 304 保留（零下載）
                                        ├ 200 覆寫 + 新 etag
                                        ├ 404 刪除（E6）
                                        └ 錯誤 → retryList（E4）
                                    → mergeSyncResults → saveCache(IDB)
                                    → 重建記憶體 routeCache（目前航線優先）
                                    → 目前航線有變 → buildChart + renderSummary + 更新時間
                                    →「已是最新」/「部分資料更新失敗」

離線分支（D5）：
  units[route] 存在（hasCache）→ 聚合 IDB units → routeCache → buildChart（完整操作）
  units[route] 不存在          → tab 提示「此航線尚未下載，需連網」+ 停留原航線（E2）
```

### 4.1 資料流對應 BDD 情境

| BDD 情境 | 資料流環節 |
|---------|-----------|
| 首次訪問載入全部資料並寫入快取 | loadCache=null → fetchIndex → 全量 trips → saveCache → buildChart（E2E-01） |
| 再次訪問無新資料秒開「已是最新」 | 快取立即繪圖 → decideSync=fresh → 0 trip 請求（E2E-02, INT-02） |
| 再次訪問有新資料只補載變更 | decideSync=update → diffUnits → 條件式 GET → merge → 重繪（E2E-03, INT-03） |
| 離線訪問顯示快取與橫幅 | 快取繪圖 + 離線分支：0 請求 + 橫幅 + 按鈕停用（E2E-04, INT-04） |
| 連網切未載入航線載入寫入快取 | loadRoute：記憶體 miss → IDB miss → 連網載入 → saveCache → 繪圖（E2E-05） |
| 手動更新有/無新版 | incrementalSync({force:true})：仍抓 index → decideSync 照跑（E2E-06/07） |
| 背景比對失敗可重試（E3） | fetchIndex 失敗 → compare_failed → 排程重試 / 手動更新重試（E2E-10） |
| 增量部分失敗保留舊版（E4） | fetchUnit 錯誤 → applyUnitResult failed → mergeSyncResults 記 retryList（E2E-11） |
| 伺服器移除檔案（E6） | 404 → applyUnitResult removed → 本地刪除（E2E-13） |
| 斷線重連自動恢復 | online 事件 → syncState ∈ {offline, compare_failed, partial} → backgroundCompare（E2E-18, INT-07） |

### 4.2 競態與並發（沿用既有 + 新增）

- **既有機制不動**：`loadToken`（快速切航線只套用最新請求）、`AbortController`（卸載中止）、Promise pool concurrency 8、記憶體 routeCache。
- **新增**：`syncing` 旗標防並行增量同步（手動更新與背景比對互斥）；同步完成重建記憶體 routeCache 時只影響「資料有變更的航線」，目前航線資料未變 → 不重繪（避免同步完閃爍）；F-25（增量更新與使用者操作競態）沿用 loadToken 語意——同步重建記憶體時若使用者已切航線，僅在目標為目前航線時 buildChart。

## 5. 生命週期

### 5.1 快取版本管理（D7）

| 層 | 版本載體 | bump 時機 | 效果 |
|----|---------|-----------|------|

### 5.2 Service Worker 生命週期（T6）

```

  → activate：skipWaiting + clients.claim + 刪舊版 cache
  → fetch：僅同源 + shell 命中 → SWR（cache-first + 背景 revalidate）；navigation → cache-first fallback network；
```

- SW 與資料層完全解耦：SW 的更新不觸發資料重同步，資料更新由 `meta.version` 控制（D1）。

## 9. 基礎架構設定

### 9.1 GitHub Pages 下 SW 註冊注意事項

- **頁面路徑**：`https://yuhaoliaosideproject.github.io/AirTicketsPrice/web/index.html`；`sw.js` 置於 `web/`，以**相對路徑** `navigator.serviceWorker.register('sw.js')` 註冊 → scope 自動為 `/AirTicketsPrice/web/`（子路徑部署不需改路徑前綴）。
- **scope 邊界 = 結構性「不攔 api/」**：`api/` 位於 `/AirTicketsPrice/api/`，在 SW scope（`/web/`）之外，**即使想攔也攔不到**——這使 D1「SW 只兜 shell、資料層純 JS」成為結構性保證，而非僅靠程式碼自律。
- **Secure context 限制**：SW 僅在 HTTPS（或 localhost）註冊；`file://` 開啟時註冊失敗 → 靜默降級為純記憶體快取（頁面仍可用，僅無離線開頁兜底）。
- **HTTPS 環境**：GitHub Pages 為 HTTPS，無混合內容問題；`api/` 同源請求不需 CORS 設定（既有）。

### 9.2 Cache-Control 現況與 SW 更新

- GitHub Pages 對靜態檔回 `cache-control: max-age=600`（實測）：
  - **app shell**：離線開頁不再依賴這 10 分鐘的 HTTP 快取——SW Cache Storage 是情境 D 的保證層（方案 B 被否決的原因，取捨 #1）。
  - **sw.js 本身**：瀏覽器每次導覽檢查 SW 更新；`max-age=600` 使新 shell 約 10 分鐘內全量生效，不需額外 header 設定。
  - **資料層**：index.json 一律 `cache:'no-cache'`；trip 檔首次 GET 走瀏覽器預設快取（ETag 重新驗證），之後由 JS 條件式 GET 接管（與 HTTP 快取無關）。
- 本機開發：`python -m http.server 8000` 以 `http://localhost` 開啟（localhost 為 secure context，SW 可註冊）；不要用 `file://` 驗證離線開頁（無 SW）。

### 9.3 Spike S1 驗證結果（2026-08-15 實測）

| 驗證項 | 結果 |
|--------|------|
| `api/index.json` 回應含 ETag | ✅ `etag: "6a7f9bfb-231e"` |
| 帶 `If-None-Match: <etag>` | ✅ **304**（零 body） |
| 帶 `If-Modified-Since` | ✅ **304** |
| 不存在的 trip 檔 | ✅ **404** |
| 靜態檔 `cache-control` | `max-age=600` |

→ **S1 通過**：GitHub Pages 完整支援 ETag / If-None-Match / If-Modified-Since，方案 C 的條件式增量同步（D4）在正式環境可行。備援不變：edge 異常回 200 時全量覆寫，功能正確僅少增量節省；B1 後顆粒度變大（4 unit/航線）增量價值反而上升。

**Spike S2–S4 驗證狀態（T9 回歸時確認）**：

| Spike | 驗證方式 | 狀態 |
